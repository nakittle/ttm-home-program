# การบ้านหลังนวด (TTM Home Program)

ระบบติดตามการทำท่าฤๅษีดัดตนที่บ้านหลังรับบริการนวดไทย ผลงานต้นแบบในการแข่งขัน Thai Traditional Medicine Digital Health & AI Hackathon 2026 (Track 4 นวดไทยและเวลเนส)

**ระบบสาธิต:** https://ttm-home-program.vercel.app

## ภาพรวม

แพทย์แผนไทยสั่งท่าฤๅษีดัดตนตามแผ่นของกรมการแพทย์แผนไทยและการแพทย์ทางเลือกให้ผู้ป่วยเป็นรายบุคคล และส่งให้ผู้ป่วยผ่าน QR บนใบนัด ผู้ป่วยทำท่าที่บ้านตามเสียงอ่านภาษาไทย โดยกล้องโทรศัพท์ช่วยจับเวลาค้างท่า ผลการทำท่า ระดับปวด และสัญญาณอันตราย (ธงแดง) จะส่งกลับถึงคลินิกก่อนนัดครั้งถัดไป และกรมฯ เห็นภาพรวมว่าผู้ป่วยทำตามแผนจริงร้อยละเท่าใด

ระบบทำหน้าที่ส่งต่อคำสั่งของผู้ประกอบวิชาชีพและแสดงเนื้อหาตามเอกสารทางการเท่านั้น ไม่วินิจฉัยโรค ไม่เลือกท่าแทนผู้ประกอบวิชาชีพ และไม่ประเมินว่าท่าถูกหรือผิด

## การเข้าใช้ระบบสาธิต

| หน้า | ผู้ใช้ | การเข้าใช้ | การทำงาน |
|---|---|---|---|
| `/clinic` | คลินิก | เข้าคลินิกทดลองได้ทันทีโดยไม่ต้องใช้รหัส หรือใช้รหัสคลินิกและ PIN | สร้างแผน พิมพ์ใบนัด A6 พร้อม QR ดูรายการผู้ป่วยเรียงตามความเร่งด่วน รับทราบธงแดง และตั้งค่ากฎธงแดงระดับ 🟡/⚪ |
| `/p/{code}#{secret}` | ผู้ป่วย | สแกน QR บนใบนัด | ให้ความยินยอม เพิ่มนัดลงปฏิทิน ตอบคำถามคัดกรอง ทำท่าพร้อมกล้องหรือปุ่ม บันทึกระดับปวด และลบข้อมูลของตนเอง |
| `/dtam` | กรมฯ | เปิดดูได้โดยไม่ต้องใช้รหัส | แสดงเฉพาะตัวเลขรวม ศูนย์ที่มีน้อยกว่า 5 แผนจะไม่แสดงตัวเลข |
| `/lab` | ผู้พัฒนา | เปิดดูได้โดยไม่ต้องใช้รหัส | ปรับเกณฑ์การตรวจท่าด้วยกล้อง และบันทึกจุดข้อต่อเป็นไฟล์ JSON |

ข้อมูลในระบบสาธิตเป็นข้อมูลจำลองทั้งหมด ประกอบด้วยศูนย์สาธิต 3 แห่ง แผนประมาณ 60 แผน ย้อนหลัง 8 สัปดาห์ และมีป้าย "ข้อมูลจำลอง" กำกับ

## การใช้ปัญญาประดิษฐ์ (AI)

| จุดที่ใช้ | เทคโนโลยี | ข้อมูลเข้า → การประมวลผล → ผลลัพธ์ | การจัดการข้อมูล |
|---|---|---|---|
| จับเวลาค้างท่า | MediaPipe Pose (โมเดลเปิด ทำงานในเบราว์เซอร์) | ภาพจากกล้อง → จุดข้อต่อ 33 จุด → กฎเรขาคณิตของแต่ละท่า (`content/postures.json`) → สถานะ "อยู่ในท่า/ยังไม่อยู่ในท่า" และตัวจับเวลา | ประมวลผลในโทรศัพท์เท่านั้น ไม่บันทึกหรือส่งภาพออก |
| เสียงอ่านภาษาไทย | Gemini TTS (สร้างไฟล์เสียงไว้ล่วงหน้า) | ข้อความจากแผ่นท่าของกรมฯ → ไฟล์เสียง | ส่งเฉพาะข้อความของกรมฯ ไม่มีข้อมูลผู้ป่วย |
| ธงแดง | กฎตายตัว (ไม่ใช้ AI) | คำตอบคัดกรองและระดับปวด → กฎ 16 ข้อ (`content/redflags.json`) พร้อมแหล่งอ้างอิง → ระดับการตอบสนอง | ประเมินทั้งในโทรศัพท์และที่เซิร์ฟเวอร์ |

## ความปลอดภัยและข้อมูลส่วนบุคคล

- ระบบไม่เก็บชื่อ เลขประจำตัวประชาชน HN หรือเบอร์โทรศัพท์ของผู้ป่วย ใช้รหัสแผนเท่านั้น คลินิกจับคู่รหัสแผนกับ HN ในระบบของคลินิกเอง
- รหัสลับของแผนอยู่หลังเครื่องหมาย `#` ในลิงก์ จึงไม่ถูกส่งไปยังเซิร์ฟเวอร์ในที่อยู่เว็บ และเซิร์ฟเวอร์เก็บไว้เฉพาะค่า SHA-256
- ข้อมูลเก็บใน Supabase ภูมิภาคสิงคโปร์ ซึ่งแจ้งผู้ป่วยในหน้าขอความยินยอม และลบเมื่อปิดแผนครบ 90 วัน
- ผู้ป่วยถอนความยินยอมและลบข้อมูลของตนเองได้ทุกเมื่อ
- กรมฯ เห็นเฉพาะตัวเลขรวม ไม่มีข้อมูลรายบุคคล

## เทคโนโลยี

Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4, Supabase (PostgreSQL), MediaPipe Tasks Vision, zod, jose และทดสอบด้วย Vitest ระบบติดตั้งบน Vercel ภูมิภาคสิงคโปร์ (`sin1`) ให้อยู่ใกล้ฐานข้อมูล

เอกสารออกแบบอยู่ที่ [`docs/superpowers/specs/2026-10-04-home-program-design.md`](docs/superpowers/specs/2026-10-04-home-program-design.md) และแนวทางการออกแบบหน้าจออยู่ที่ [`DESIGN.md`](DESIGN.md)

## การติดตั้งเพื่อพัฒนา

```bash
npm install
cp .env.example .env.local
npm run dev
```

กำหนดค่าใน `.env.local` ตามคำอธิบายในไฟล์ `.env.example` คำสั่ง `npm run dev` และ `npm run build` จะดาวน์โหลดโมเดล MediaPipe ให้โดยอัตโนมัติ

หากยังไม่กำหนดค่า Supabase ระบบจะใช้ที่เก็บข้อมูลในหน่วยความจำ ซึ่งข้อมูลจะหายเมื่อเริ่มระบบใหม่ กรณีรัน `npm run build && npx next start` โดยไม่มี Supabase ต้องกำหนด `ALLOW_MEMORY_STORE=1` เพิ่ม (ห้ามกำหนดค่านี้บน Vercel) และสร้างข้อมูลจำลองได้ด้วยคำสั่ง

```bash
curl -X POST http://localhost:3000/api/demo/reset -H "content-type: application/json" -d "{\"token\":\"<DEMO_RESET_TOKEN>\"}"
```

## คำสั่ง

| คำสั่ง | การทำงาน |
|---|---|
| `npm test` | รันชุดทดสอบทั้งหมด (Vitest) |
| `npm run typecheck` / `npm run lint` | ตรวจสอบชนิดข้อมูลและรูปแบบโค้ด |
| `npm run build` | สร้างระบบสำหรับใช้งานจริง |
| `npm run seed` | สร้างข้อมูลจำลองใน Supabase ครั้งแรก (ต้องกำหนด `DEMO_CLINIC_PIN`) |
| `npm run seed -- --refresh` | สร้างแผนจำลองใหม่ให้เป็นวันที่ปัจจุบัน โดยคงคลินิก PIN และแผนอื่นไว้ |
| `npm run seed -- --reset` | ล้างฐานข้อมูลแล้วสร้างใหม่ ระบบจะไม่ดำเนินการหากยังมีแผนที่ป้องกันไว้ (`PROTECTED_PLAN_CODES`) เว้นแต่ระบุ `--wipe-everything` |
| `npm run tts -- --sample` | สร้างไฟล์เสียงตัวอย่าง 3 ไฟล์ จากนั้นใช้ `npm run tts` สร้างไฟล์ที่เหลือ |
| `npm run images` | สร้างภาพแผ่นท่า `public/postures/*.webp` จากไฟล์ต้นฉบับ |
| `npm run purge` | ลบข้อมูลของแผนที่ปิดครบ 90 วัน |

## การตั้งค่า Supabase และ Vercel

1. สร้างโปรเจกต์ Supabase ในภูมิภาคสิงคโปร์
2. เปิด SQL Editor วางเนื้อหาจาก `supabase/schema.sql` แล้วกด Run
3. คัดลอก Project URL และ service_role key จาก Settings → API ไปกำหนดใน `.env.local` และใน Environment Variables ของ Vercel
4. ตรวจสอบว่า Functions ของ Vercel อยู่ที่ภูมิภาคสิงคโปร์ (`sin1`) ตามที่กำหนดใน `vercel.json`
5. สร้างข้อมูลจำลองด้วย `npm run seed` จากเครื่องของผู้พัฒนา และก่อนนำเสนอให้ใช้ `npm run seed -- --refresh` เพื่อปรับวันที่ให้เป็นปัจจุบัน

โปรเจกต์ Supabase แบบไม่มีค่าใช้จ่ายจะหยุดทำงานอัตโนมัติเมื่อไม่มีการใช้งานระยะหนึ่ง หากทุกหน้าที่ใช้ฐานข้อมูลแจ้งว่าระบบขัดข้อง ให้กด Restore project ในหน้า Supabase แล้วรอประมาณ 2–3 นาที

## ที่มาของเนื้อหา

ท่าและภาพจากแผ่น "ยืดเหยียด...ดัดตน...พ้นโรค ด้วยท่าฤๅษีดัดตน" ของกรมการแพทย์แผนไทยและการแพทย์ทางเลือก พ.ศ. 2569 ชุดที่ 1 (ออฟฟิศซินโดรม) ชุดที่ 2 (หัวไหล่ติด) และชุดที่ 6 (เข่าเสื่อม) ทุกท่าในระบบแสดงที่มาและลิงก์ไปยังเอกสารต้นฉบับ

กฎธงแดงจัดทำโดยคณะผู้พัฒนาจากเอกสารของกรมฯ ได้แก่ แนวทางเวชปฏิบัติสำหรับหน่วยบริการปฐมภูมิ (CPG_PCU) และแนวทางเวชปฏิบัติการดูแลผู้ป่วยระยะกลางด้วยการแพทย์แผนไทย (พ.ศ. 2564) กฎทุกข้อระบุแหล่งอ้างอิงและเลขหน้า และอยู่ระหว่างการตรวจรับรองโดยผู้ประกอบวิชาชีพ

ระบบนี้เป็นผลงานต้นแบบเพื่อการแข่งขัน ไม่ใช่เครื่องมือวินิจฉัยโรค
